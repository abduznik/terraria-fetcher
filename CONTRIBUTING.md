# Contributing

This is a static site with no build step. Plain HTML, CSS, and JavaScript, deployed as-is
to GitHub Pages.

## Local development

No install required. Serve the folder with any static file server, for example:

```
python -m http.server 8000
```

Then visit `http://localhost:8000`.

## Refreshing the item database

`data/items.json`, `data/npcs.json`, and `data/meta.json` are generated by
`scripts/fetch_data.py`, which pulls from the Official Terraria Wiki's Cargo API. Run it
with:

```
python scripts/fetch_data.py
```

This is normally run by the `Fetch Terraria Data` GitHub Actions workflow (on a monthly
schedule or manual dispatch), not by hand — only run it locally if you're changing the
script itself and need to verify output.

## Code style

- No comments unless they explain a non-obvious *why* (a workaround, a hidden constraint).
  Don't describe what the code already makes clear.
- No emojis anywhere — not in UI copy, commit messages, code, or documentation. Use real
  Terraria item/NPC icons (see `assets/js/*.js` for the `wikiIconUrl()` pattern) wherever
  a small visual marker is wanted instead.
- Keep builds and checklist content factually accurate against the current dataset in
  `data/items.json` — verify item/armor names exist before referencing them.
- Match the existing wood-panel Terraria theme in `assets/css/style.css` rather than
  introducing a new visual style.

## Pull requests

- Keep PRs scoped to one change. A bug fix doesn't need an accompanying refactor.
- If you change `builds/builds.json` or `checklist/checklist.json`, verify every item
  name you reference actually exists in `data/items.json` first.
- Update `CHANGELOG.md` under `[Unreleased]` for any user-visible change.

## Reporting bugs / requesting features

Use the issue templates. Check `ROADMAP.md` first — your idea may already be tracked
under a milestone.
